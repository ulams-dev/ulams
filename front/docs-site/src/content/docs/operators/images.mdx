The `admin` and `front` images (`ghcr.io/ulams-dev/admin`, `ghcr.io/ulams-dev/front`) are static builds
served by [nginx-unprivileged](https://hub.docker.com/r/nginxinc/nginx-unprivileged). They contain no
PHP, run as a non-root user (uid 101) and listen on **port 8080**. Point your reverse proxy at
`admin:8080` and `front:8080`; the production example in
[Self-hosting](/operators/self-hosting/) already does.

```bash
docker run --rm -p 8080:8080 \
  -e REACT_APP_TENANT_API_HOST_PATTERN='{slug}.admin.localhost=>http://{slug}.localhost' \
  ghcr.io/ulams-dev/admin:latest
```

Images are published for `linux/amd64` and `linux/arm64`. Pin `ghcr.io/ulams-dev/admin:sha-<short>` or a
release tag rather than `latest`; use the same tag as the other ulams images
([Upgrades](/operators/upgrades/#image-tags), [Container images](/developers/container-images/#tags-platforms-attestations)).

## Settings

Settings are plain environment variables, read when the container starts:

| Image | Variables | Examples |
|---|---|---|
| `admin` | every `REACT_APP_*` | `REACT_APP_TENANT_API_HOST_PATTERN`, `REACT_APP_API_URL`, `REACT_APP_STUDIO_URL`, `REACT_APP_SENTRYDSN`, `REACT_APP_YBUG` |
| `front` | every `VITE_APP_*` | `VITE_APP_API_URL`, `VITE_APP_TENANT_API_HOST_PATTERN`, `VITE_APP_SENTRYDSN`, `VITE_APP_FIREBASE_*` |

### Image service (admin)

`REACT_APP_IMAGE_SERVICE` chooses how the admin builds image URLs (course cards, avatars, images inserted in the
rich text editor):

| Value | Behaviour |
|---|---|
| `php` (default) | The API resizer, `/api/images/img?path=...&w=...`. Nothing changes if you do not set it. |
| `cloudflare` | `/cdn-cgi/image/...` on the admin host, with the file's public storage URL as source. Needs a Cloudflare zone with Image Transformations in front of the admin host, and the storage host in that zone (or allow-listed). A failed transformation serves the original file. Images inserted in the editor are stored as their plain public URL instead of an API resizer URL. |
| `noop` | Originals, no resizing. Use it as a kill switch. |

Files without a public URL keep using the API resizer in every mode. Optional companions:
`REACT_APP_IMAGE_SOURCES` (comma-separated storage origins allowed as sources, in addition to the API origin) and
`REACT_APP_IMAGE_TRANSFORM_ORIGIN` (serve transformations from another host; empty: the admin host). To go back to
the original files, set `noop` and restart the container; no rebuild is needed. Design: ADR 0193.

Documentation links in the admin panel and the front come from `ULAMS_DOCS_URL`, set as
`REACT_APP_ULAMS_DOCS_URL` (admin) and `VITE_APP_ULAMS_DOCS_URL` (front). It defaults to
`https://ulams-dev.github.io/ulams/` until `docs.ulams.app` serves the docs.

At start the container writes them to `/runtime-config.json`; the page fetches that file before the
app boots. Only variables with the prefix above are written, so other secrets in the container
environment are never served. Open `https://<host>/runtime-config.json` to see what a running
container exposes. To change a setting, restart the container.

Leave `REACT_APP_API_URL` empty for a multi-tenant admin: it derives the tenant API from the page host
with `REACT_APP_TENANT_API_HOST_PATTERN`, for example `{slug}.admin.example.com=>https://{slug}.api.example.com`.

## What the image serves

- `/` and every path without a file extension return `index.html` (single page app).
- Hashed assets are cached for a year; `index.html`, the service workers and `runtime-config.json` are
  never cached.
- `GET /healthz` returns `200 ok` for load balancer and orchestrator checks.

<Aside type="caution" title="Headers come from your proxy">
The image sets no security headers. Add the Content-Security-Policy, HSTS and the other headers in the
reverse proxy; the production example Caddyfile does this for the admin with its `app_csp_admin` snippet, which sends the CSP in report-only mode until `ULAMS_CSP_HEADER` is set to `Content-Security-Policy` (see [Security headers](/operators/security-headers/)). Add HSTS there once HTTPS works on every host.
</Aside>

A consultation is a one-to-one (or small group) session with a tutor. The author defines the
consultation, its duration and the terms they propose. A learner who has access to it (usually by
buying its product) reports a term; a tutor approves or rejects it; at the approved time both join a
Jitsi room.

Two packages are involved:

| Package | Role |
|---|---|
| `consultations` | Consultations, proposed terms, booked terms, the approve/reject/change flow, reminders |
| `consultation-access` | Requests for **free** access: a learner asks for a consultation with proposed dates, an administrator approves one date or rejects the request |

## Who uses it

- **Administrators** create consultations and review consultation requests.
- **Tutors** (author or teachers of a consultation) approve, reject, move and finish terms. With
  the default roles they have only the `-own` permissions, so the admin menu entry, which needs
  `consultation_list`, is hidden for them; they work through the API or a front.
- **Learners** buy consultations, report terms and send consultation requests.

### Consultation requests

`/other/consultation-access` (Other activities → Consultation Requests). One row per request:
description, user, consultation, the proposed dates, meeting link, created date and status
(`pending` or `approved`).

- **Approve** a proposed date. Choose the meeting type:
  - *Custom*: paste a meeting link;
  - *Jitsi*: the admin panel generates a public `https://meet.jit.si/<uuid>` link;
  - *Pencil Spaces* (only when the package is installed): no link is sent, and the API queues
    `CreatePencilSpaceJob`, which creates a Pencil Space for the author and the learner and stores
    its link.
- **Disapprove** with an optional reason. The request is deleted and the learner is notified.

Approving fails if the request is already approved or if the date is already full
(`max_session_students`). The menu entry can be hidden with the setting
`hideInMenu-OtherConsultation-access`.

## Term lifecycle

1. The learner gets access (product purchase or user submission). A booked consultation row is
   created for them.
2. The learner reports a term: `POST /api/consultations/report-term/{id}`. It fails with 400 if
   the term already has `max_session_students` bookings. Status becomes `reported`. If the
   product is a bundle, the term is approved automatically (`App\Listeners\UpdateReportTermListener`).
3. A tutor approves (`approved`) or rejects (`reject`) it.
4. A tutor or administrator with `consultation_change_term` can move the term
   (admin calendar or `POST .../change-term/{id}`).
5. From the start time until start + duration, `GET /api/consultations/generate-jitsi/{id}`
   returns the room data. Learners need an approved term; tutors need at least one approved term
   at that time. The room uses the [Jitsi configuration](/admin/webinars/#video-conference-configuration-jitsi).
6. A tutor marks the session finished with `POST /api/consultations/finish-term/{id}`.

## API endpoints

| Method and path | Purpose |
|---|---|
| `GET/POST /api/admin/consultations`, `GET/PUT/DELETE /api/admin/consultations/{id}`, `POST /api/admin/consultations/{id}` | Admin CRUD |
| `GET /api/admin/consultations/{id}/schedule` | Booked terms (admin calendar) |
| `POST /api/admin/consultations/change-term/{termId}` | Move a term |
| `GET /api/admin/consultations/users/assignable` | Users that can be author or teacher |
| `GET /api/consultations`, `GET /api/consultations/{id}` | Public list and detail |
| `GET /api/consultations/me`, `GET /api/consultations/my-schedule` | Learner's consultations, tutor's schedule |
| `POST /api/consultations/report-term/{id}`, `GET .../proposed-terms/{id}` | Book a term |
| `GET .../approve-term/{id}`, `GET .../reject-term/{id}`, `POST .../change-term/{id}`, `POST .../finish-term/{id}` | Tutor actions |
| `GET /api/consultations/generate-jitsi/{id}` | Room data |
| `GET /api/admin/consultation-access-enquiries`, `POST .../approve/{proposedTermId}`, `POST .../disapprove/{id}` | Admin review of requests |
| `GET/POST /api/consultation-access-enquiries`, `GET/PATCH/DELETE .../{id}`, `GET .../{id}/join` | Learner's own requests; `join` returns the meeting link (a Pencil Spaces direct-login link for Pencil Spaces rooms) |

Full list: [API endpoints](/reference/api-endpoints/).

## Events and notifications

| Event | Recipient | E-mail | SMS |
|---|---|---|---|
| `ReportTerm` | Author and teachers | yes | yes |
| `ApprovedTerm` / `ApprovedTermWithTrainer` | Learner / tutor | yes | yes |
| `RejectTerm` / `RejectTermWithTrainer` | Learner / tutor | yes | yes |
| `ChangeTerm` | Learner | yes | no |
| `ReminderAboutTerm` | Learner, one day and one hour before | yes | yes |
| `ReminderTrainerAboutTerm` | Tutor, before the term | yes | yes |
| `ConsultationAccessEnquiryAdminCreatedEvent` | Consultation author, on a new request | yes | no |
| `ConsultationAccessEnquiryAdminUpdatedEvent` | Consultation author, on an edited request | no | no |
| `ConsultationAccessEnquiryApprovedEvent` | Learner | yes | no |
| `ConsultationAccessEnquiryDisapprovedEvent` | Learner, with the reason | yes | no |

Reminders come from the scheduled job `ReminderAboutConsultationJob`: the one-hour reminder runs
every minute and the one-day reminder hourly. See [Scheduled jobs](/reference/scheduled-jobs/),
[Templates](/admin/templates/) and [Events and notifications](/reference/events-and-notifications/).

## Settings

- Jitsi or JaaS: see [Webinars](/admin/webinars/#video-conference-configuration-jitsi).
- Pencil Spaces: `PENCIL_SPACES_API_URL` and `PENCIL_SPACES_API_KEY`, or the `pencil_spaces.api_url`

## Known limitations

- If Pencil Spaces is not configured or its API fails, `CreatePencilSpaceJob` only logs the error:
  the request stays approved without a meeting link and the learner gets no approval e-mail.
- The "Jitsi" option for requests uses the public `meet.jit.si` service, not the configured Jitsi
  server.
- The learner site (`front/web`) lists consultations read-only; booking and requests need the
  legacy learner app or a custom front. See [Learners](/learners/).

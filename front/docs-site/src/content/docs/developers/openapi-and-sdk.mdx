The OpenAPI document is generated from `@OA\` docblocks in the PHP code by
`darkaonline/l5-swagger` 11 (`zircote/swagger-php` 6). The TypeScript SDK in `front/sdk` turns that
document into types with `openapi-typescript`. Decision record:
[OpenAPI docs from Swagger annotations](/decisions/api/0006-openapi-docs-from-swagger-annotations/).

## Where the annotations live

| Annotation | Where | Example |
|---|---|---|
| `@OA\Info`, `@OA\SecurityScheme` (`passport`, bearer JWT) | `api/packages/core/src/Http/Controllers/CoreController.php` | once for the whole API |
| Operations (`@OA\Get`, `@OA\Post`, …) | a **Swagger interface** per controller, `src/Http/Controllers/Swagger/<Name>ControllerSwagger.php`; the controller implements it | `BookmarkControllerSwagger` in `api/packages/bookmarks_notes` |
| Request schemas (`@OA\Schema`) | on the FormRequest class | `CreateBookmarkRequest` → schema `BookmarkCreateRequest` |
| Response schemas | on the API Resource class | `BookmarkResource` |

Keeping the operation docblocks on an interface keeps the controller readable and makes the
interface the place to check the documented contract. See
[Adding an endpoint](/developers/adding-an-endpoint/) for a full example.

<Aside type="caution" title="Register the package's source path">
l5-swagger scans an explicit list of directories: `documentations.default.paths.annotations` in
[`api/config/l5-swagger.php`](https://github.com/ulams-dev/ulams/blob/main/api/config/l5-swagger.php)
(`app/` plus one `base_path('packages/<name>/src')` per package). A new package's endpoints do not
appear in the document until you add its `src` directory there.
</Aside>

## Generating the document

```bash
make -C api swagger-generate
# = docker compose exec api bash -c "php artisan l5-swagger:generate"
```

The result is `api/storage/api-docs/api-docs.json`. The `api/` folder is mounted into the
container, so the file appears on the host at that path; there is nothing to copy out. It is
git-ignored.

- Swagger UI: http://api.localhost/api/documentation (or `http://<slug>.localhost/api/documentation`).
- With `L5_SWAGGER_GENERATE_ALWAYS` (default `true`) the UI regenerates the document on every
  request, which also refreshes the JSON file.
- CI runs `php artisan l5-swagger:generate` in the `platform` PHPUnit shard, so a broken annotation
  fails the build.

## Regenerating the SDK types

`@ulams/sdk` is a framework-free client (`createClient(...)`) used by `front/web`. Its request
paths are typed by the generated file:

```ts
// front/sdk/src/types.ts
import type { components, paths } from "./generated/openapi.ts";
export type ApiPath = keyof paths;
```

Every `request()` call in `front/sdk/src/client.ts` takes an `ApiPath`, so calling a path the API
does not document is a type error. Paths that are not in the document yet are cast
(`"/api/demo/login" as ApiPath`).

<Steps>

1. Generate the OpenAPI JSON (above).

2. Regenerate the types from the repository root:

   ```bash
   corepack yarn workspace @ulams/sdk generate
   # openapi-typescript ../../api/storage/api-docs/api-docs.json -o src/generated/openapi.ts
   ```

3. Typecheck the SDK and its consumers, then commit `front/sdk/src/generated/openapi.ts` with the
   change that caused it:

   ```bash
   corepack yarn turbo run typecheck --filter=@ulams/sdk --filter=@ulams/web
   ```

4. Update the CLI from the same document, so every new operation has a command (or an exclusion with a
   reason) and the coverage check stays green:

   ```bash
   corepack yarn workspace ulams sync-spec   # api-docs.json -> front/cli/spec/openapi.json
   corepack yarn workspace ulams generate    # spec + overrides -> src/generated/commands.ts
   corepack yarn workspace ulams coverage    # fails on an operation without a command
   ```

   CI fails (`CLI spec is current`, `sync-spec.mjs --check`) when this step was skipped.

   The course builder and Living Course are the exception: their commands are hand-written
   (`front/cli/src/commands/builder.ts`, `living.ts`) and list the endpoints they cover.

</Steps>

If you generate the JSON in a container that does not mount the source (for example from a
published `api` image), copy it out first:

```bash
docker cp <container>:/var/www/html/storage/api-docs/api-docs.json api/storage/api-docs/api-docs.json
```

## Response schemas and operation ids

Operations that the CLI turns into noun commands carry a typed 2xx response and an `operationId` equal to the
CLI command id (`templates.list`, `adapt.versions-add`). Typed answers follow one pattern, defined in
`api/app/Http/Controllers/Swagger/ResponseSchemas.php`:

- `ApiEnvelope` is the answer of every JSON endpoint: `success` and `message`. A page also has `meta` (`ApiPage`).
- `<Name>Response` is the envelope plus `data` typed by the resource the controller returns (`TemplateResponse`,
  `AdaptSourceListResponse`, `InteractivePackagePageResponse`); an answer without data (a delete) is `ApiEnvelope` itself.
- The data schemas (`TemplateData`, `PageData`, ...) mirror the Resource classes field for field. When a resource
  changes, change its schema in the same commit.

To type a new endpoint: add the data schema and its `<Name>Response` to `ResponseSchemas.php`, then reference it in the
operation: `@OA\Response(response=200, description="...", @OA\JsonContent(ref="#/components/schemas/<Name>Response"))`
and `operationId="<noun>.<verb>"`. Regenerate the document and run the refresh commands of the CLI (`sync-spec`,
`generate`, `coverage`) and the SDK. Non-JSON answers (a file, Markdown) keep their own media type and no envelope.

## Operation ids and the quality gate

Every operation has a readable, unique `operationId`. The ones above are curated; the rest are derived from the
route, in the annotation, so they stay put when code moves: the path without `api`, a path parameter as `by-<name>`,
then the HTTP method (`GET /api/admin/courses/{id}/access` is `admin.courses.by-id.access.get`). Choose a better name
when you add an operation; the id must be lowercase dotted words and unique.

`yarn workspace ulams spec-quality` (a CI step, `front/cli/scripts/spec-quality.mjs`) fails when an operation has no
readable unique id, or no typed 2xx response. A 204 needs none. Operations whose answer is not JSON (redirects, file
downloads, HTML pages, event streams) are listed with a reason in `front/cli/spec/untyped-responses.yaml`; the check also
fails on an entry that is no longer needed.

Two schemas cover the operations that have no resource schema yet: `ApiEnvelope` (`success`, `message`, `data` of any
shape, `meta` for a page) for the endpoints that answer the usual envelope, and `ApiJson` (a free-form object) for the
ones that build their answer by hand. Both are placeholders for a precise schema: replace them with a `<Name>Response`
as described above when you touch the endpoint.

## PHP SDK

`sdk-php/` is a Composer package (`ulams/sdk`, PHP 8.1+, Guzzle) generated from `front/cli/spec/openapi.json` by
openapi-generator (pinned Docker image, `sdk-php/generate.sh`). `lib/` is generated and never edited by hand; `src/` is a
thin wrapper:

```php
use Ulams\Sdk\Api\AdminKnowledgeApi;
use Ulams\Sdk\Client;
use Ulams\Sdk\Pagination;

$ulams = Client::make('https://academy.example.com', getenv('ULAMS_TOKEN'));
$exports = $ulams->api(AdminKnowledgeApi::class)->knowledgeExportsList();

foreach (Pagination::items(fn (int $page) => $ulams->api(Api\AdminCoursesApi::class)->adminCoursesGet(page: $page)) as $course) {
    echo $course['title'], "\n";
}
```

The client sends the bearer token, an `Idempotency-Key` on every request that changes data and an `X-Request-Id` on all of them.
Method names are the operation ids in camel case (`knowledge.exports.list` is `knowledgeExportsList`). CI regenerates the
package and fails on any difference, so run `sdk-php/generate.sh` after changing the API and commit the result. The
tests run the generated classes against canned answers (`composer test` in `sdk-php/`). The package is not published to
Packagist yet.

## Limits of the current document

Every operation has a typed answer now, but many of them are only the envelope with a free-form `data`, so those
fields are `unknown` in `openapi.ts` and `mixed` in the PHP client. The response types in `front/sdk/src/types.ts`
are written by hand from real API responses; replacing them with generated ones follows as the placeholder schemas are
replaced with precise ones. The endpoint list is on
[API endpoints](/reference/api-endpoints/), the reference on [API reference](/developers/api-reference/)
and usage examples of the client on [SDK usage](/developers/sdk/).

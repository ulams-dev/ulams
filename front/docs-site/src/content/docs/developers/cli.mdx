`ulams` is a command line tool for people and AI agents. It talks to the same REST API as the admin
panel and the learner frontend, through [`@ulams/sdk`](/developers/openapi-and-sdk/). Every command is
defined once in a registry, so the help, the JSON schema (`ulams schema`), the
[CLI reference](/reference/cli/) and the MCP server cannot drift apart.
Decision records: [ADR 0072](/decisions/0072-agent-first-cli-command-registry/) (registry) and
[ADR 0073](/decisions/0073-cli-machine-contract/) (output contract).

<Aside type="note" title="Install from the repository for now">
The package is not published to npm yet. From a checkout of the repository:

```bash
corepack yarn install --ignore-engines
corepack yarn workspace ulams build
node front/cli/dist/ulams.mjs --version      # or link the bin, see "Use ulams from Claude Code"
```
</Aside>

## Log in

Tokens are per instance (each tenant has its own signing keys), so a profile is one instance plus one
token. Credentials are stored in `~/.config/ulams/credentials.json` (mode 0600; `$ULAMS_CONFIG_DIR`
overrides the directory), and the CLI never prints a token.

```bash
# Demo tenants (DEMO_MODE=true): the seeded admin, tutor or student
ulams login --url http://coffee.localhost --demo admin

# A password (one line on stdin, never a flag)
printf '%s' "$PASSWORD" | ulams login --url https://school.example.com --email me@example.com --password-stdin

# A token you already have
printf '%s' "$TOKEN" | ulams login --url https://school.example.com --token-stdin

ulams whoami            # user, roles, instance, where the token came from
ulams profiles list     # saved profiles; `ulams profiles use <name>` switches
```

Password logins use the API's one-month token, which has the full permissions of the user. Scoped
tokens and browser login (`ulams login --device`) arrive with the server work in
[ADR 0074](/decisions/0074-scoped-personal-access-tokens/) and [ADR 0075](/decisions/0075-device-login/);
until then `--device` answers "not available on this server".

For CI and agents no files are needed: set `ULAMS_URL` and `ULAMS_TOKEN`. Precedence is flag, then
environment, then profile. A profile token is never sent to another `--url`.

## Output contract

When stdout is not a terminal (or with `--json`) every command prints one JSON document:

```json
{ "ok": true, "contract": 1, "command": "api", "data": [], "meta": { "page": 1, "perPage": 25, "total": 0, "lastPage": 1, "nextPage": null } }
```

Failures print `{ "ok": false, "error": { "code", "message", "hint", "status", "retryable", "requestId", "details" } }`
and exit with a stable code: 0 ok, 2 usage or input, 3 not logged in, 4 forbidden, 5 not found, 6 conflict,
7 API validation, 8 rate limited, 9 server or network, 10 wait timeout, 11 confirmation required, 12
feature disabled, 13 diff found. The full table is in the [CLI reference](/reference/cli/).

The CLI never prompts unless you pass `--interactive` (or run `login` in a terminal). Every input has a
flag, and `--input @file.json` (or `-` for stdin) supplies a whole input object that explicit flags override.

## Call any endpoint

```bash
ulams api --list --filter quiz                         # endpoints of the bundled API spec
ulams api GET /api/admin/courses --query per_page=5 --json
ulams api PUT /api/admin/courses/{id} --param id=12 --body '{"title":"New"}' --dry-run
ulams api DELETE /api/admin/courses/12 --yes
```

`GET` is a read, `DELETE` is destructive and needs `--yes` (exit 11 with the plan otherwise), other
methods are writes and honour `--dry-run`.

## Discover the commands

```bash
ulams schema --json                 # every command, input JSON Schema, kind, scopes, exit codes
ulams describe api                  # one command
ulams --help
```

Run `ulams schema` once at the start of an agent session; it works without credentials.

## Commands for everything the admin panel does

Noun commands are generated from the API's OpenAPI document by method and path (`courses list`,
`lessons create`, `users get 12`, `quizzes update`, ...), with a curated override file for names and a few
hand-written commands where the generic one is not enough. Every operation of the API is either covered
or deliberately excluded; the [coverage matrix](/reference/cli/coverage/) is checked in CI.

```bash
ulams courses list --title Kube --per-page 5            # filters are flags
ulams courses list --all --fields id,title,status        # every page; NDJSON with --output ndjson
ulams courses get 12                                     # lessons and topics included
ulams courses publish 12                                 # idempotent
ulams access grant --course 12 --user 34 --group 5       # enrol (alias: ulams enrol)
ulams settings set global companyName "Acme Academy"
ulams theme set --accent '#C2552D'
ulams courses export 12 --out course-12.zip
```

List commands take `--page`, `--per-page`, `--all` and `--limit`. Names that are not obvious: learner
endpoints are under `my` (signed in) and `public`, tokens under `tokens`. `ulams schema` lists them all.

### Topics of every type

| Command | Creates |
|---|---|
| `topics create-richtext --markdown @file.md` | rich text from Markdown (or `--html`) |
| `topics create-oembed --url …`, `create-video --youtube-url …` | an embedded video or page |
| `topics create-video --file v.mp4` | uploaded video; waits for processing (`--no-wait` prints `video:<id>`) |
| `topics create-file --file doc.pdf` | PDF, image or audio, by extension |
| `topics create-scorm --package pkg.zip [--sco id]` | SCORM package; several SCOs without `--sco` exit 2 with the choices |
| `topics create-cmi5`, `create-h5p`, `create-liascript` | the same pattern for each package type |
| `topics create-quiz --input @quiz.yaml` | a GIFT quiz with its questions |
| `topics create --topicable <class> --value …` | any other registered type |

### Dry run, confirmation and long operations

`--dry-run` makes no change: for updates it fetches the current resource and prints a diff, for deletes
it shows the resource. Destructive commands exit 11 with that plan until you pass `--yes`. Long
operations wait by default (`--timeout 600`); `--no-wait` prints a handle such as `video:42` that you can
give to `ulams operations get|wait`; a timeout exits 10 and names the handle.

## Declarative apply

`ulams apply --file course.yaml` takes YAML or JSON documents (`apiVersion: ulams.dev/v1`; kinds `Course`
with nested lessons and topics, `User`, `Group`, `Page`, `Setting`, `Access`). Objects are found by title,
email, name or group and key, only changed fields are written, and a second run performs no writes.
`--dry-run --exit-code` exits 13 when the plan has changes; `--prune` also deletes lessons, topics and
access entries missing from the manifest (it needs `--yes`). `ulams get Course "Kubernetes 101" --output yaml`
exports a live course as a manifest. A full example is in
[`front/docs-site/examples/cli`](https://github.com/ulams-dev/ulams/tree/main/front/docs-site/examples/cli).

## The short version

1. Open or pick an issue, and for anything non-trivial agree the scope there first.
2. Plan larger work in `docs/plans/phase-N.md`; the product owner approves the plan before
   implementation starts.
3. Branch as `phase-N/short-description`, commit with Conventional Commits, one concern per
   commit, tests in the same commit.
4. Record every decision as an ADR and update this site in the same branch.
5. Open the pull request, fill in the checklist and wait for green CI and a review.

<Aside type="caution" title="Security problems">
Never report a vulnerability in a public issue. Follow the [security policy](/contributing/security-policy/).
</Aside>

The contributing guide, code of conduct and security policy pages are rendered from
`CONTRIBUTING.md`, `CODE_OF_CONDUCT.md` and `SECURITY.md` at the repository root, so GitHub and
this site always show the same text. Edit those files, not the pages.
